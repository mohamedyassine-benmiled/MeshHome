# Native engine build and verification

The Android UI must not be mistaken for a complete, tested Meshnet client without this component.

## Source and dependencies

`native/` implements JNI against libtelio **core**, pinned to commit `c15a3bd60340e9cc0da74d93fe50b3b875e9e052` (8.2.0 development tree). The helper fetches that exact revision into ignored `vendor/libtelio` and applies `native/patches/android-socketpair.patch`. It uses `Device`, `DeviceConfig`, `Config`, `AdapterType::NepTUN` and a custom `Protector`. This avoids hand-written UniFFI bindings. Socket failures are propagated and failed sockets are quarantined because some upstream callbacks discard errors.

The source pin requires Rust 1.99.1 according to upstream's build script. Install Rust/rustup, CMake, and a current Android NDK (r28+ recommended). Follow the upstream repository's native prerequisite instructions if additional platform build tools are needed. Never download private Nord CI artifacts or enable libmoose telemetry to get a public build working.

```powershell
python scripts/build-native.py --ndk C:\path\to\android-ndk --abi arm64-v8a
.\gradlew.bat :app:assembleDebug
```

The script also supports x86_64 emulators and armeabi-v7a, but only arm64-v8a has been built here. It does not install prerequisites or accept SDK licenses automatically. Build each desired ABI before assembling. `native/Cargo.lock` was generated by the successful native build and is used with `--locked`.

The helper refuses a different upstream revision and never resets local vendor changes. It copies a stripped library to `app/src/main/jniLibs/<abi>/` and the upstream GPL text to `app/src/main/assets/licenses/libtelio-LICENSE.txt`. The original unstripped binary remains under `native/target`.

For a workstation-specific convenience wrapper, see `scripts/build-native-local.ps1`; general contributor builds should use `scripts/build-native.py` with their own Rust, CMake and NDK installation.

## Ownership and data path

1. Android establishes a narrowly routed VPN for selected, still-installed packages.
2. Kotlin reads the only Android TUN. Virtual-DNS packets go to the local DNS responder. Other routed IP packets go through an AF_UNIX datagram socketpair to NepTUN, preserving packet boundaries. Unmodified `TunSocket::new_from_fd` performs `TUNGETIFF`, which rejects socketpairs. The checked-in Android-only patch uses NepTUN's existing numeric-FD constructor for this path instead. It adopts the FD without the ioctl; non-Android behavior is unchanged.
3. Rust owns a duplicated socketpair FD on every start success/error path. Kotlin owns the Android TUN and the other socketpair endpoint.
4. Native external sockets call Kotlin synchronously. Kotlin protects each socket, then binds it to the chosen Android `Network`. Failure returns an `io::Error` from the native Protector. Because the pinned NepTUN callback discards that error, the bridge first atomically replaces any failed socket with an unusable AF_UNIX socket (`dup2`, preserving upstream FD ownership). Resource exhaustion preventing this quarantine aborts the process rather than permitting fallback traffic. DNS upstream sockets and Nord HTTPS requests also bind to the chosen network.
5. Changed native peer/relay states and protection/fatal errors push a JNI callback; status snapshots are requested on events rather than every second. Running the engine does not prove the server or its services are reachable. JNI API version 3 prevents the app from silently using an older incompatible library. JNI entry points use the Android namespace `com.mybm.meshhome`.
6. Network/routing/DNS changes tear down the old session and create a new one. Other peer-map updates use `updateMap` without restarting the tunnel. A socket bound to a lost Wi-Fi network is not allowed to migrate to cellular.
7. The native map is restricted to enabled domain targets, and libtelio's battery preset configures transport keepalives. A single blocking packet poll is woken by a shutdown pipe, not an idle timeout. See `BATTERY.md` for native-timer limitations and measurement requirements.

### Relay-only constraint

Direct discovery is intentionally disabled (`features.direct = null`). Source review found that WG-STUN's `new_internal_udp` sockets are not routed through the external Protector on Android. They assume the client's own UID participates in its OS VPN; MeshHome excludes its own UID so default-network monitoring and control requests remain on the real physical network. Simply enabling direct discovery would therefore break that internal path and could send discovery traffic on the wrong network. Supporting direct peers requires an explicit internal-packet/UID-routing redesign and new network-failure tests, not just toggling a feature flag. Relay connections use the externally protected/bound sockets and remain supported.

## Validation status / release gates

The arm64 Rust bridge has compiled, including the API-version, event callback, and in-place map-update integration. ELF load segments were previously checked for 16 KB alignment; dependencies are standard Android libraries. One Android 13 phone/account has exercised basic peer connectivity, local DNS responses and disconnect. Service recovery, latest package-namespace migration, updated firewall instrumentation, and broad network behavior remain unverified; no battery measurement has been taken. Compilation and limited phone testing do not establish production readiness or leak-free behavior. The Android configuration-only build intentionally remains possible without the native library; Connect then reports a missing/incompatible component rather than opening a dummy VPN.

Required before a release:

- Rebuild the pinned bridge with the checked-in lockfile and patch; do not silently update upstream or dependencies.
- Verify NepTUN accepts the datagram socketpair on Android (read/write and nonblocking behavior), shutdown closes all FDs, and 16 KB page-size loading works.
- Verify every external socket goes through the Protector before connecting/sending, and inject protection/bind failures to prove no fallback traffic escapes.
- Test two real peers over relay transport, peer firewall permissions, IPv4/IPv6, and HTTPS reverse-proxy access. Direct peer optimization is a separate follow-up requiring the internal-routing redesign above.
- Test Wi-Fi loss/mobile fallback, home bypass when SSID is visible/hidden, SSID permission revocation, captive portals, process death, service stop, and VPN consent revocation.
- Test DNS UDP/TCP, malformed packets, oversized replies, Private DNS, application DoH, caches, and multiple domains/devices. The small local TCP endpoint is not a general-purpose TCP stack.
- Test the optional background-location disclosure/settings flow for SSID access and verify that no location-coordinate API is called. Google Play policy review would be required before publishing this permission use.
- Live Nord token, registration/retry/deregistration, and map APIs need verification with the user's account, on-device. Never send a real token in chat.
