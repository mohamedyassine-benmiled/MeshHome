# 0.3.2 development build

Addresses the phone's native startup failure: the pinned upstream firewall
requires a separately loaded `libfirewall.so` which is not packaged and is
referenced by upstream as an internal artifact. Native feature `firewall` is
now null; enforcement instead happens at the Android packet boundary in
`ClientFirewall`. JNI API version 3 requires the matching app/native pair.

This is a restricted client-only filter, not equivalent to upstream's full
firewall. Only local Meshnet addresses to configured target addresses can open
TCP/UDP tuple pinholes. TCP requires an outbound SYN and matching SYN-ACK;
unsolicited incoming traffic is dropped. Local DNS replies use a separate path;
native packets cannot bypass the filter through that path. State is bounded to
4096 flows and expires lazily without a polling timer. Android's TCP stack still
validates transport sequence/window state; the filter is not a TCP implementation.

Unsupported protocols (including ICMP/ping and ICMP errors), fragmented packets
and IPv6 extension headers are dropped. Long-idle TCP sessions can expire after
five minutes, UDP after one minute. These restrictions may affect applications
and path-MTU/error handling; this is not a general LAN gateway or incoming-service
implementation. The replacement requires further security review before a
production release.

Build validation: arm64 native engine and app APK rebuilt successfully; 55 JVM
tests pass; Android lint reports no warnings/errors; APK signature and 16 KB ZIP
alignment checks pass; packaged native bytes match the newly compiled library.
Four packet-pump instrumentation tests compile. The previous three tests passed
on the phone before this filter change; the updated tests and native startup
fix have not yet been tested on-device.

Artifact: `dist/MeshHome-0.3.2-arm64-debug.apk`, with adjacent SHA-256 file.
Older documentation describes the 0.3.0 baseline; this note supersedes its native
firewall, JNI-version and test-count descriptions.
