# 0.3.6 — explicit disconnect

Disconnect previously relied on Android delivering `onDestroy` after
`stopService`/`stopSelf`. An established VPN can remain system-bound, so that
is not a reliable place to initiate tunnel teardown.

The activity now sends the explicit STOP action. STOP, revocation and terminal
account errors all invoke idempotent shutdown immediately: mark the service
stopping, prevent further reconciliation/retries, halt the packet reader and
close its TUN, unregister listeners, and queue native cleanup. `onDestroy`
retains the same shutdown as a fallback. Existing saved credentials/settings
are unchanged.

Android build, 55 JVM tests and lint passed. Installed 0.3.6 on the Android 13
phone, connected successfully (1/1 peer, running packet pump), then tapped the
actual Disconnect button through ADB UI input. Verified that the service no
longer exists and the MeshHome VPN network is removed. Left the phone
disconnected, as requested by the user's attempted disconnect.

Other connectivity, battery, network-transition and repeated shutdown/race
tests remain separate runtime gates.
